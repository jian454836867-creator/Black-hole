### 检索质量修复（重要）
1. **发现并修复 min-max 归一化 bug**：`search.js` 的 `normalizeScores` 把向量分数做 min-max 归一化（最差→0，最好→1），导致"问李白"时最差的无关词条也被拉到 1.0，摧毁绝对阈值判断。改为**直接用余弦相似度**（`1 - L2²/2`），不再归一化
2. **发现 bge-small-zh 短句退化**：实测 `cos(你好, 李白) ≈ 0.71` > `cos(苏轼黄州, 李白) ≈ 0.53`，短句 embedding 挤向"通用语义中心"，与任何查询都算"相关"
3. **三层防线**：
   - 入库侧：`filter.js` 价值过滤（<12 字短句不入库，含主题词例外；寒暄/纯标点直接丢）
   - 召回侧：`SIM_STRONG = 0.70` 强相关线，top1 低于此 → 直接回"请持续投喂"，不调大模型、不返回凑数引用
   - 上下文侧：只把 >= 0.70 的命中注入上下文并进引用列表，低于此完全丢弃
4. **验收**：
   - 问"李白是什么风格"（库里没有）→ `{"answer":"库中暂无相关观点。请持续投喂相关知识...","citations":[],"noKnowledge":true,"latencyMs":11}` ✅
   - 问"苏轼的黄州"（库里有）→ 正常回答 + 2 条强相关引用 ✅
   - 问"留白是什么"（库里有）→ 正常回答 + 1 条引用 ✅
5. **微信端过滤**：`weixin.js` 收到消息先过 `isValuable()`，无价值消息（你好/在吗/纯标点等）静默忽略不入库，不消耗模型

## 四、关键坑位（已解决，记录在开发计划 §7）

1. transformers.js 4.3.1 不读 HF\_ENDPOINT → worker 内 `env.remoteHost = 'https://hf-mirror.com/'`
2. vec0 表不能声明 `INTEGER PRIMARY KEY` 列（rowid 即主键）；knn 查询必须 `ORDER BY distance LIMIT ?`，JOIN 会破坏 knn 语义
3. FTS5 unicode61 按 CJK 单字分词，整句短语不命中 → 「整句 OR CJK-bigram(AND)」组合
4. onnxruntime-node 的 npm postinstall 被拦截 → 手动 `node script/install` 下二进制
5. insight\_ids 与 vec rowid 错位 → nextRowId 取两表 MAX(rowid)+1；resetAll 需清 insight\_ids
6. 模型输出 dims \[seq, 512]，需按 subarray 切分（pooling:'mean', normalize:true 时）
