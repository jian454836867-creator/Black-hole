## 1. 产品定位

一个**永远在本地运行**的极简「黑盒外脑」：

- 用户只做两件事：**投喂**（拖文件 / 微信发图文）和 **提问**（对话框）。
- AI 在后台默默完成：解析 → 提取观点 → 向量化 → 跨时空比对 → 发现「观点碰撞」。
- 唯一出口：本地 **时间线瀑布流** + **全局对话框**（+ 微信晚间聚合通知）。

### 核心铁律（不可违反）

| # | 铁律 | 含义 |
|---|------|------|
| 1 | 双入口一出口 | 入口 = 本地 GUI（主工作台）+ 微信 iLink（移动传感器）；出口 = 时间线 + 对话框 |
| 2 | 静默处理、低频通知 | 后台解析/比对零打扰；仅「新碰撞」触发 UI 徽章或微信晚 8 点聚合通知 |
| 3 | 三态判定、绝不强凑 | 观点关系只有 `parallel`（默认）/ `merge`（同构升华）/ `conflict`（适用边界）；无 90% 把握一律 parallel |
| 4 | 时间线不前置 | 历史观点位置不变；跨时空碰撞只以徽章附着在新节点上 |
| 5 | 隐私端云路由 | `private`（默认微信来源）绝不触网；`normal` 数据仅把检索命中的片段发云端模型合成 |

## 2. 技术栈

| 层 | 选型 | 备注 |
|----|------|------|
| 前端 | Tauri + Vue3 + TailwindCSS | 极简聊天框 + 拖拽区 + 时间线瀑布流 |
| 后端 | Node.js | 基于现有 Black hole 架构（**本机尚无该代码，需从零起步或用户提供**） |
| 存储 | SQLite 单文件 + sqlite-vec（向量）+ FTS5（全文） | 5 张表，无图数据库 |
| 本地向量模型 | Xenova/bge-small-zh-v1.5（INT8 ONNX，约 24MB） | 纯 CPU，512 维，跑在 worker_threads |
| 云端 LLM | DeepSeek API | V4-Flash 廉价提取；V4-Pro 冲突边界合成；利用缓存控费 |
| 移动桥接 | 微信 iLink 协议 `src/bridges/weixin.js` | 文档称「已跑通」，但**本机工作区没有该文件**（见 §7 假设） |

## 3. 数据库设计（SQLite，5 张表）

1. `raw_files` — 原始素材，不可变，溯源用；`privacy_level`（默认 private）、`file_type`、`source_url`、`raw_text`。
2. `insights` — 观点/洞见核心节点；`content`、`summary`、`tags`(JSON)、`source_file_id`。
3. `relations` — 静默碰撞结果；`insight_a_id`/`insight_b_id`、`relation_type`（merge|conflict）、`explanation`、`user_confirmed`（0 待确认 / 1 收录 / -1 忽略）。
4. `vec_insights` — vec0 虚拟表：`insight_id TEXT` + `embedding float[512]`。
5. `fts_insights` — FTS5 虚拟表：`insight_id`、`content`、`tags`。

## 4. 核心工作流

### 流程 1 — 入库（Ingest）
拖入文件 / 微信图文 → 提取纯文本 → 打 `privacy_level`（微信默认 private）→ DeepSeek 或本地小模型提取 1–3 条 insights 落库 → 异步任务：向量化入 `vec_insights`、文本入 `fts_insights`。

### 流程 2 — 随时问（Chat & RAG）⚠️ Step 1 首要验证点
提问 → 双路召回（query 向量 Top-K + FTS5 Top-K，**7:3 权重融合**）→ 召回 insights 及关联 relations 组装 Prompt → DeepSeek 生成回答；`private` 且无本地模型时退回「仅本地词条回答并标注」。

### 流程 3 — 静默合成（Synthesis）
新 insight B 入库 → 后台取历史 insight A 向量比对 → 相似度 **> 0.82** 触发三态判定 Prompt（严格 JSON）→ merge/conflict 写入 `relations`（`user_confirmed=0`）→ UI 显示 ✨已融合 / ⚖️有冲突 徽章 → 点击滑出面板，用户「确认收录」置 1。

## 5. 里程碑（严格按序，逐步验收）

| Step | 名称 | 预估 | 任务 | 验收标准 |
|------|------|------|------|----------|
| **1** | 本地检索层闭环 ⚠️ 当前重点 | 0.5–1 天 | 装 @huggingface/transformers 加载 bge-small-zh INT8 ONNX；建 5 张表；实现 `search(query)`（vec + FTS5 并行，7:3 融合 Top-K） | 20 条模拟数据（含「苏轼」等专名），3 个维度 Query，**单次查询 < 500ms**，语义+关键词召回均正确 |

| 4 | 前端徽章与滑出面板 | 1.5 天 | 时间线渲染（有 relations 显示徽章）；徽章点击滑出面板展示逻辑；「确认收录」「忽略」落库 | UI 正确，裁决状态落库更新 |
| 5 | 微信 iLink 接入与通知 | 1.5 天 | iLink 消息以 private 静默入库并回「👌 已入黑盒」；晚 8 点定时拉取当天新增 relations 聚合推送微信 | 微信发文字 → 电脑端入库；次日收到晚间碰撞通知 |

总预估：约 **7–8 天**（含 Step 1 的 0.5–1 天）。

## 6. 关键防坑（必须落实）

1. **锯齿状智能防范**：三态判定 Prompt 强约束「没有 90% 以上把握输出 parallel」；宁漏 merge 不产垃圾数据。
2. **主线程防卡顿**：Embedding 推理全部放 `worker_threads`，不卡 UI。
3. **微信 iLink**：Token 会过期 → 重连逻辑；通知严禁实时轰炸 → 仅晚 8 点聚合。
4. **成本控制**：日常提取用 V4-Flash；仅冲突边界深思考用 V4-Pro + 缓存。

## 8. 非功能要求（从铁律推导）

- 单机可离线运行（云端 LLM 可选增强）；数据全部在本地单文件 SQLite。
- 后台任务（向量化、比对、定时推送）不得阻塞 GUI 响应。
- `raw_files` 不可变：入库后只增不改，保证溯源。
- 隐私路由是代码级强制：`private` 数据在「发送云端」前必须被拦截。
