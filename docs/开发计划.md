> 依据 `需求整理.md`。执行原则：**5 Step 串行，每步验收通过才进入下一步**；每步结束提交一次可运行的检查点。

## 1. 总体策略

- 从零在工作区 `E:\GONGZUOTAI\2` 起步（无 openclaw-mini 存量代码，见假设 A1/A2）。
- 先立「引擎核」（DB + 向量 + 检索 + 模型），GUI 与云端在后两步接入。
- 所有重活（ONNX 推理、比对扫描）进 `worker_threads`；主进程只做编排。
- 隐私路由做在存储/服务层，而不是 UI 层 —— `private` 数据从代码上就没有路径触网。

## 3. 内部接口约定（自定，替代 openclaw-mini 存量约定）

- `db.js` → `getDb()`：返回 better-sqlite3 实例（已建表）。
- `repo.js` → `insertRawFile(file)`、`insertInsight(i)`、`getInsight(id)`、`listRelationsFor(insightId)`、`confirmRelation(id, state)`。
- `embedder.js` → `embed(texts: string[]): Promise<number[][]>`（worker 内跑，批量）。
- `search.js` → `search(query, {k=5}): Promise<Hit[]>`，`Hit = {insightId, score, via: 'vec'|'fts'|'both'}`。
- `llm.js` → `llm.extractInsights(text, {privacy})`、`llm.answer(question, context)`、`llm.judge(a, b)`（仅 normal 数据可达云端；privacy 路由在调用方拦截）。

## 4. 分步执行计划

### Step 1 — 本地检索层闭环（0.5–1 天）⚠️ 当前
**任务**
1. `npm init` + 依赖：`better-sqlite3`、`sqlite-vec`、`@huggingface/transformers`、`dotenv`。
2. `schema.sql` 落 5 张表；`db.js` 初始化（vec 扩展 load、FTS5 触发器保持 insights 与 fts_insights 同步）。
3. `embed-worker.js`：`pipeline('feature-extraction', 'Xenova/bge-small-zh-v1.5', {quantized:true})`，首用自动下载缓存。
4. `embedder.js`：worker 池（默认 1 个，CPU 推理）+ 简单队列，暴露 `embed()`。
5. `search.js`：并行执行
   - 向量路：`SELECT insight_id, 1 - distance FROM vec_insights WHERE embedding MATCH ? ORDER BY distance LIMIT ?`（余弦）
   - 关键词路：`SELECT insight_id, bm25(fts_insights) FROM fts_insights WHERE fts_insights MATCH ? LIMIT ?`
   - 归一化后 7:3 加权融合，返回 Top-K。
6. `seed.js`：20 条覆盖「通用语义 / 专名（苏轼、量子纠缠）/ 领域术语（微服务、止损）」的模拟数据入库。
7. `verify-step1.js`：3 条不同维度 Query（如「苏轼被贬黄州时的心境」「微服务拆分的代价」「止损的哲学」），断言：召回正确（人读核对 + 关键词路命中专名）且**单次查询 < 500ms**（取模型热后的中位数）。

**验收**：`npm run verify:step1` 全绿。
**风险预案**：prebuild 缺失 → `npm rebuild better-sqlite3`；模型下载失败 → 检查代理，缓存目录 `data/model-cache`。

### Step 2 — 入库流 + 问答流（2 天）
**任务**
1. `ingest.js`：txt/md/html(可选)/图片(OCR 后置，先文本) → 纯文本 → `raw_files`（privacy 参数，默认 normal，微信源 private）→ `llm.extractInsights`（未配 Key 时走「标题/首句启发式」降级）→ `insights` → 异步 `embed()` 写 vec + fts。
2. `llm.js`：DeepSeek 官方 endpoint；V4-Flash 提取 / V4-Pro 合成；响应缓存（按 prompt hash 存表或文件）。
3. `rag.js`：`search()` 召回 → 拼 insights + 关联 relations 入 Prompt → 生成回答 → 回答尾部附引用 `[insight_id]`。`private` 且无本地模型 → 仅本地词条回答 + 显式标注「⚠️ 未触网」。
4. `api.js`：本地 HTTP（`/ingest`、`/ask`、`/timeline`、`/relations/:id`）。
5. GUI（Tauri + Vue3 + Tailwind）：拖拽区（文件 → `/ingest`）、极简对话框（一问一答 + 引用角标）、时间线初版（按 created_at 倒序平铺，无徽章）。
**验收**：拖一篇本地文档 → 对话框提问 → 得到**带引用**的回答。

### Step 3 — 合成引擎与三态判定（2 天）
**任务**
1. `comparator.js`：新 insight 向量化后，对历史 `vec_insights` 全量扫（规模小，直接 SQL 距离排序），取相似度 **> 0.82** 的候选。
2. `judge.js`：对候选逐对发三态判定 Prompt，**强约束 JSON**：`{"relation":"parallel"|"merge"|"conflict","explanation":"..."}`，并写明「无 90% 把握必须 parallel」；解析失败 → parallel。
3. merge/conflict 写 `relations`（`user_confirmed=0`）；parallel 丢弃。
4. 队列化：多对新 insight 串行判定，防 API 风暴；结果可查（`/relations?pending=1`）。
**验收**：造三组数据（强关联如「沉没成本」↔「别为打翻的牛奶哭泣」；强冲突如「止损」↔「长期持有不卖」；无关联），查库验证 relation_type 正确、无关联零记录。

### Step 4 — 前端徽章与滑出面板（1.5 天）
**任务**
1. 时间线卡片：无 relations → 普通卡片；有 → 右上角 ✨已融合 / ⚖️有冲突 徽章（按类型着色）。
2. 点击徽章 → 右侧滑出面板：A/B 观点对照 + `explanation` + 「确认收录」（置 1）/「忽略」（置 -1），调 `/relations/:id`。
3. 已收录的徽章加勾态；忽略后徽章灰显可恢复。
**验收**：UI 三态展示正确；裁决后刷新页面状态保持（落库验证）。

### Step 5 — 微信 iLink 接入与通知（1.5 天）
**前置**：用户提供已跑通 `src/bridges/weixin.js`（假设 A1）。
**任务**
1. 桥接接入：iLink 收到图文 → 以 `private` 入 `ingest()` → 回复「👌 已入黑盒」；Token 过期 → 重连逻辑（指数退避）。
2. 定时任务：每日 20:00 拉取当天新增 `relations`（confirmed=0 或 1）→ 聚合文本 → 微信推送；当天无新增不推送；**严禁实时单条轰炸**。
**验收**：微信发文字 → 电脑端时间线出现新节点（private）；次日 20:00 收到聚合通知。

## 7. Step 1 落地备注（实际实现与文档差异）

1. **HF_ENDPOINT 不生效**：transformers.js 4.3.1 不读 `HF_ENDPOINT` 环境变量，需在 worker 内 `env.remoteHost = 'https://hf-mirror.com/'` 才能走国内镜像（本机 huggingface.co 直连超时）。
2. **vec0 主键陷阱**：`vec0(embedding float[512])` 不能声明 `INTEGER PRIMARY KEY` 列（会与 rowid 冲突报 "Only integers are allowed for primary key values"），rowid 即映射键；knn 查询必须 `ORDER BY distance LIMIT ?`（JOIN 会破坏 knn 语义）。
3. **FTS5 中文**：unicode61 按 CJK 单字分词，整句短语不命中；用「整句 OR CJK-bigram(AND)」组合匹配。
4. **模型加载**：`pipeline('feature-extraction', MODEL, { quantized: true })` + 调用时 `{ pooling: 'mean', normalize: true }`，输出 dims [seq, 512]；bge 系加检索指令前缀。
5. **onnxruntime-node**：npm postinstall 被拦截时手动 `node node_modules/onnxruntime-node/script/install` 下载二进制。
6. 复现命令：`npm run seed`（重置+灌 20 条，约 135ms）→ `npm run verify:step1`。
